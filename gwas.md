# Genome Wide Association Analysis

This pipeline uses [REGENIE](https://rgcgithub.github.io/regenie/) software to perform genome-wide association analysis.
The following steps are performed when running the pipeline :

- Conversion of imputed genomic data (.vcf) to plink2 pgen/pvar/psam format (likely one set per chromosome). 
- Step 1 of REGENIE using genomic data before imputation
- Step 2 of REGENIE using the converted imputed data
- Concatenation of REGENIE step 2 outputs into one single genome-wide output file

## Run pipeline using docker or apptainer (singularity)

### Clone GitHub repo

```bash
 git clone https://github.com/giant-consortium/association_analysis.git
```

### Update parameters and paths to input files

- Create a copy of the `parameters_gwas.txt` file in the directory you plan to use to launch the pipeline.   
- Modify it with your input file path/names and parameters you want to use to run the GWAS, see inputs needed below.    

#### In/Out paths 
- `path_to_data` : your local path where to find the input qced array files (bed, bim, fam)   
- `path_to_imputed_data` : your local path where to find the imputed data files (vcf, or plink files in either bed or pgen format)   
- `path_to_output_dir` : your local path for output files (will be created if it does not exist yet)  
- `imputed_file_pattern` : glob pattern (relative to `path_to_imputed_data`) selecting the genotype files to use, **including their extension**, which also tells the pipeline how to read them: `chr*.vcf.gz` or `chr*.vcf` for VCF files, `chr*.bed` for PLINK1 filesets (bed/bim/fam), `chr*.pgen` for PLINK2 filesets (pgen/pvar/psam). 
- `path_to_sex_file` : path to the sex file, output of the phenotype step. It is needed to convert chrX VCFs, since plink2 needs the sex of the participants to import chrX; leave the value empty (`path_to_sex_file=`) if there is no chrX VCF. The format is a tab-delimited file with the header line `#FID`, `IID`, `SEX`, then one line per participant with the FID and IID exactly as in the `.fam` of the QC'd genotypes and the sex coded `M`/`F` or `1`/`2`. 
- `genome_build` : genome build of the imputed VCFs, `hg38` by default (TOPMed). Used to split the chrX pseudoautosomal regions.
- `genotype_output_format` : genotype format used to prepare REGENIE step 2 input, either `pgen` (default, fastest, hard-call dosages) or `bgen` (retains continuous imputation dosages, as required by some consortia protocols).


#### REGENIE step 1/2 parameters
- `study_QC_name` : Always set study_name to match the base name of your PLINK files (no file extensions). The pipeline accepts files in .bed/.bim/.fam.  
- `step1_max_nvar` : optional maximum number of variants of the QC'd genotypes (`study_QC_name`) used for REGENIE step 1. If the genotypes contain more variants than this, they are randomly thinned down to this number (plink2 `--thin-count`, with a fixed seed so the same variants are kept on every run). The thinned copy is written to `step1_output/`, used for step 1 only, and deleted once step 1 has finished to save space; its sample IDs and sex are identical to the original. Leave empty (`step1_max_nvar=`) for no thinning.  
- `output_prefix` : Study name you want to use as prefix for outputs generated by this pipeline. For each input genetic file going to step2 (eg chrN), the resulting output filename will be output_prefix_chrN.regenie    
- `path_to_pheno_file` : path to the phenotype file. The phenotype file is a tab-delimited file starting with the 2 columns FID IID and other columns containing your phenotype data. See [REGENIE documentation](https://rgcgithub.github.io/regenie/options/#phenotype-file-format) for file format.   
- `pheno_col` : columns from the phenotype file to run gwas on (`pheno_col`): column names without quotes, separated by commas (no spaces)   
- `path_to_covar_file` : path to covariate file, The covariate file is a tab-delimited file starting with the 2 columns FID IID and other columns containing your covariates. See [REGENIE documentation](https://rgcgithub.github.io/regenie/options/#covariate-file-format) for file format   
- `cont_covar_col` : columns referring to **continuous** covariates from the covariate file, to be used for the gwas (`cont_covar_col`) : column names without quotes, separated by commas (no spaces), e.g. `PC1,PC2`. Can be left empty. 
- `cat_covar_col` : columns referring to **categorical** covariates from the covariate file, to be used for the gwas (`cat_covar_col`) : column names without quotes, separated by commas (no spaces), e.g. `GENO_BATCH`. Can be left empty.

  Covariates should capture technical/genotyping confounding (e.g. genotyping batch or plate, genotype PCs). Do **not** include variables such as age or sex: they are already regressed out of the rank-normalised residualised phenotypes.
- `path_to_samples_to_keep` : path to the keep file. The keep file is a tab-delimited file with 2 columns containing the participants FID and IID that you want to use in your gwas, but no colnames
- `regenie_step1_flags` : string to add to REGENIE Step 1 command, by default it is `"--qt --bsize 1000"` where `--qt` stands for continuous/quantitative traits and changing it to `--bt` would be done for categorical/binary traits. For more info on which flags to use, please refer to [REGENIE documentation](https://rgcgithub.github.io/regenie/options/#basic-options).
- `regenie_step2_flags` : string to add to REGENIE Step 1 command, by default it is `"--qt --bsize 400 --maxCatLevels 25 --minMAC 1"` (continuous/quantitative traits). A common option for binary trait analysis can be `"--bt --firth --approx --pThresh 0.01 --firth-se --af-cc"`. For more info on which flags to use, please refer to [REGENIE documentation](https://rgcgithub.github.io/regenie/options/#basic-options).

### Launch pipeline 

The pipeline runner script takes a single required option, `--docker`, `--apptainer` or `--singularity`, to run the analysis using any of those platforms. The container image (`step4_assoc.tar` for docker, `step4_assoc.sif` for apptainer/singularity) is downloaded automatically by the runner the first time, if it is not already in the repo folder. If the container is already there and the runner is launched from a terminal, it asks whether to download it again and overwrite it (default: no; in non-interactive runs such as batch jobs the existing container is always kept):    

Run with docker
```bash
bash path_to/assoc_pipeline_runner.sh --docker
```
Run with apptainer
```bash
bash path_to/assoc_pipeline_runner.sh --apptainer
```
Run with singularity
```bash
bash path_to/assoc_pipeline_runner.sh --singularity
```
Apptainer is the direct continuation of the open-source Singularity project (renamed in 2021), and Singularity(CE) remains compatible with the same `.sif` image and bind-mount syntax, so the same `step4_assoc.sif` works with either binary.

### Resume pipeline

The pipeline is checkpointed: each stage (VCF/PLINK conversion, REGENIE step 1, REGENIE step 2 per chromosome) is skipped if its expected output already exists in `path_to_output_dir`. If a run fails partway through, simply re-run the same command — completed stages are skipped and the pipeline resumes from where it stopped. To force a stage to redo its work, delete its output files before re-running.

### Test data 

Simulated data that can be used to test the pipeline, all in the `test_input` folder of this repo :    
- QC'd array data : `test20Kvar.bed/.bim/.fam` (10,000 samples, FID = IID), to be used as `study_QC_name=test20Kvar`  
- Phenotype, covariate (`GENO_BATCH`, `PC1`, `PC2`), sex and keep files : `pheno_file.txt`, `covar_file.txt`, `sex_file.txt`, `samp_fid_iid_EUR.txt`  
- Imputed data : `test_input/imputed_data/chr21.vcf.gz`, `chr22.vcf.gz` and `chrX.vcf.gz`, same 10,000 samples as the array data, with sample IDs coded `<FID>_<IID>` as output by the TOPMed imputation server. These are small subsets of variants (about 500 for chr21/chr22, 450 for chrX) and the genotypes are simulated, so the association results are not meaningful: they are only meant to check that the pipeline runs end to end.
